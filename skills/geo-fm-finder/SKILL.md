# Geo foundation model finder

One skill, two modes, working on the same catalog. Everything lives in this skill's
folder (called `<skill>` below; run scripts as `python <skill>/scripts/...` from any
directory, they locate the catalog themselves):

- `database/models/<id>.json`: one record per model, validated against
  `schema/model_schema_mlm.json` (STAC MLM field names).
- `database/embeddings/<id>.json`: one record per precomputed embedding product,
  validated against `schema/embedding_schema_emb.json` (STAC Embeddings extension
  field names). `encoder_model.id` points to the model record when there is one.
- `database/INDEX.md`: generated overview, one table row per record. Regenerated by
  `catalog.py write-index`; never edit it by hand.
- `scripts/`: `recommend.py` (shortlist, compare), `catalog.py` (index, check, gaps,
  diff, write-index), `validate.py` (schemas and cross-record checks), `search.py`
  (literature search for new models).

## 1. Pick the mode

| Request | Mode | Then read |
|---|---|---|
| Describes a use case, asks which model / embedding fits, compares models | **Recommend** (read-only) | `references/recommend.md` |
| Asks to add, update, fix, refresh or scan the catalog, or names a paper or product to add | **Update** (writes records) | `references/update-catalog.md` |
| Both ("find what's new for X and tell me what to use") | Update scoped to X, then Recommend | both, in that order |
| Unclear | Recommend | `references/recommend.md` |

Read only the reference file for the chosen mode; it holds the full workflow.

## 2. Handoff from Recommend to Update

Recommend mode never writes files. While recommending, offer a **targeted** update
(not a full catalog refresh) when one of these holds:

- the user names a model or product that `catalog.py check` reports as `NEW`;
- the newest `release_date` in the catalog is more than ~3 months old and the user
  asks for recent or state-of-the-art options;
- the top candidates are held back by empty fields that matter for the decision
  (weights, parameter count, benchmarks for the user's task, years an embedding
  product covers).

Give the recommendation from the current catalog first, then ask, naming the records
and fields concerned. Switch only with the user's go-ahead. Run Update mode limited to
those records, including validation and `write-index`, then return to Recommend and
revise the answer with the refreshed records, saying what changed.

Do not commit unless asked.
